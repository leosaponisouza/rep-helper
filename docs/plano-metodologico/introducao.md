# Introdução — Plano Metodológico

Este documento descreve o **Plano Metodológico** adotado para o ciclo completo de engenharia de software da plataforma **RepHelper**. Seu objetivo é estabelecer como a equipe organiza os papéis, os rituais ágeis, as práticas de qualidade de código, o plano de testes e o faseamento de entregas (Releases e Sprints) para construir um sistema robusto em **React (PWA) + Java (Spring Boot) + PostgreSQL**.

## Sumário do Plano Metodológico

1. **[Metodologia de Desenvolvimento](metodologia.md)**: Abordagem híbrida combinando Planejamento e Modelagem Inicial (Cascata/Upfront Design) com Execução Iterativa e Incremental (**Scrum + Extreme Programming — XP**).
2. **[Organização do Projeto e Equipe](organizacao-do-projeto.md)**: Estrutura organizacional de 6 integrantes, responsabilidades detalhadas, rituais de gestão e *Definition of Done (DoD)*.
3. **[Cronograma e Roadmap de Entregas](cronograma-e-entregas.md)**: Planejamento estruturado em **3 Releases incrementais** e **6 Sprints**, mapeando cada requisito funcional (`RF001` a `RF026`) até a entrega final.
4. **[Plano de Testes e Critérios de Aceitação (BDD)](plano-de-testes-e-aceitacao.md)**: Estratégia de testes (JUnit 5, Testcontainers, React Testing Library) e cenários Gherkin (*Dado / Quando / Então*) cobrindo todas as Regras de Negócio.
